## 1\. 프로젝트 개요

### 1.1 컨셉

방문객이 탐나라공화국을 걸으며 스스로 한 권의 책을 만들어가는 체험형 웹 애플리케이션. 캐치프레이즈 **"책이 되어 걷다"**.

- 기존의 책: 이미 존재하는 텍스트를 통해 지식·지혜를 얻는 매체. 텍스트 기반의 책은 점차 힘을 잃고 있다.  
- 이 앱의 전제: 공원을 걸으며 방문객이 느끼고 생각하는 것 자체를 한 권의 책(비물리적)으로 규정한다.  
- 앱의 역할: 답을 주지 않는다. 생각의 길과 방향을 제시하는 **질문**과 **작은 행위**를 던지고, 사유에 도움이 되는 공원 내 **장소**로 안내한다.  
- 공간과의 정합: 탐나라의 LOOK & LINK LIBRARY 체계("소리를 읽다", "나를 읽다" 등 — 각 장소가 '읽기'의 한 양태)와 같은 은유 체계를 공유한다. 앱은 이 체계의 대화형 연장이다.

### 1.2 역할 구조

| 요소 | 역할 |
| :---- | :---- |
| 공원(탐나라공화국) | 백지 — 책이 쓰이는 지면. 장소들은 각자의 목소리를 가진 화자 |
| 방문객 | 저자 — 걷고, 답하고, 경로를 선택함으로써 책을 씀 |
| AI | 사서(司書)/편집자 — 장소들의 목소리를 중계하고 잇는다. 질문과 행위를 내밀되, 결정하지 않는다 |

### 1.3 핵심 설계 원칙

1. **AI는 답을 주지 않는다.** 질문·생각거리·작은 행위·갈림길만 제시한다.  
2. **선택권은 항상 방문객에게.** 다음 장소는 2\~3개의 갈림길을 이유와 함께 제시하며, 방문객이 고른다.  
3. **연속성과 연결성이 품질의 핵심이다.** 개인의 정보·고민이 장소의 특성·의미와 엮여, 도착하는 과정과 도착 후의 사유가 하나의 실로 이어져야 한다. (§5.2 '여정의 실' 참조)  
4. **길도 책의 일부다.** 스팟 사이의 이동 구간에서도 행위와 생각거리를 제공한다. 챕터는 '길 \+ 장소'로 이루어진다.  
5. **프라이버시 최소주의.** 입력된 사진·인적사항·고민·답변은 세션 중에만 처리하고 서버에 저장하지 않는다. 이메일 주소는 PDF 발송 즉시 폐기한다.  
6. **결말은 실물로.** 카페알로에서 그날의 사진·답변·경로를 엮은 한 권의 책(PDF)을 이메일로 받는다.

## 2\. 사용자 흐름 (User Flow) — 3막 구조

여정은 **이동지점 3개 \+ 종착(카페알로)** 의 고정 아크를 갖는다. AI는 현재가 몇 번째 챕터인지 인지하고 질문의 깊이와 방향을 조절한다.

\[서문 — 스타트 지점\]

  → QR 스캔, 컨셉 안내 ("당신은 오늘 한 권의 책이 됩니다")

  → 나무판(문구 목록 중 하나) 사진 촬영·업로드

  → 기초 입력: 나이대, 성별(선택), 그리고

     "지금의 고민" 또는 "오늘 읽고 싶은 것" 자유 텍스트

  → AI: 사진(선택 문구 \+ 부수 정보)과 입력을 읽고

     (a) 내부적으로 '여정의 실' 생성 (§5.2)

     (b) 첫 사유의 질문 1개

     (c) 첫 갈림길 2\~3개를 이유와 함께 제시

\[챕터 1 — 承: 감각을 열다\]                    ┐

  → \[이동\] 경로 안내 \+ 이동 중 행위 1개          │

     (예: 길가의 꽃을 잠시 보라 / 오늘내일문 앞에서 │ 이 구조가

      자신의 마음을 읽어보라 / 땅의 냄새를 맡아보라) │ 챕터 2, 3에서

     \+ 걸으며 품고 갈 생각거리 1개               │ 반복된다.

  → \[도착\] 도착 행위 \+ 장소의 목소리(보드 인용)    │ 단, 질문의

  → \[미션\] 그 장소에서의 미션 부여                │ 깊이와 방향은

     (예: 책무덤에서 사라진 것의 의미를 살펴보라 /  │ 막에 따라

      책 한 권을 뽑아 아무 페이지나 읽어보라)      │ 달라진다.

  → 방문객 답변 → 꼬리 질문(0\~2회)              │

  → 다음 갈림길 제시                            ┘

\[챕터 2 — 轉: 고민과 대면하다\]

  → 같은 구조. 질문은 여정의 실의 핵심으로 접근.

\[챕터 3 — 結을 향해: 조망하다\]

  → 같은 구조. 질문은 전환·거리두기·정리의 방향.

  → 갈림길 대신 카페알로(귀환)로 안내.

  → 귀환 경로에서 어머니방 앞을 지날 경우, 선택적 문("가장 늦게

    읽는 책을 여시겠습니까") 제시 가능 — 강요 없음.

\[에필로그 — 카페알로\]

  → 도착: "한 잔을 고르는 동안, 당신의 책을 엮겠습니다"

  → AI: 마지막 회고 질문 1개 (차를 기다리며 답하는 가벼운 것)

  → 책 생성: 제목(AI 작명), 서문(나무판 사진), 3개 챕터

    (길에서 본 것 \+ 장소에서 쓴 것), 에필로그(경로 지도)

  → 이메일 주소 입력 → PDF 발송 → 주소 즉시 폐기

  → 화면 미리보기 제공. 차를 마시는 동안 책이 도착한다.

**막별 질문 지침 (시스템 프롬프트에 반영):**

| 막 | 방향 | 질문의 결 |
| :---- | :---- | :---- |
| 서문 | 열기 | 상태 확인, 가볍고 구체적 |
| 챕터 1 (承) | 감각 | 몸·감각으로 고민에 우회 접근 |
| 챕터 2 (轉) | 대면 | 여정의 실의 핵심을 정면으로, 그러나 장소의 은유를 통해 |
| 챕터 3 (結 방향) | 조망 | 거리두기, 관점 전환, "지금 뒤돌아보면" |
| 에필로그 | 닫기 | 회고 한 문장, 무겁지 않게 |

## 4\. 데이터 정의

### 4.1 장소 사전 (spots.json)

→ **별도 문서 「장소사전 v0.2」로 작성 완료.** 10개 스팟: 미러리움, 천향랑(음악정원), 하늘등대, 어머니방, 카페알로, 노자예술관, 헌책도서관, 와룡, 나이야가라, 도자마을. 각 스팟: reading(읽기 양태), voice(장소의 목소리), mission, seeds, fits, avoid, 코스번호·인접 정보 포함.

### 4.2 경로 사전 (paths.json) — **신규, 작성 필요**

이동 구간 콘텐츠의 재료. 스팟 쌍(방향 무관)마다:

{

  "id": "path\_mirroreum\_cheonhyangrang",

  "between": \["spot\_mirroreum", "spot\_cheonhyangrang"\],

  "walk\_min": null,

  "waypoints": \[

    { "name": "자유사거리", "note": "네 갈래 길이 만나는 곳", "act\_seed": "갈림길에서 잠시 멈춰 서기" },

    { "name": "천연샘물", "note": "물을 마실 수 있는 샘", "act\_seed": "물 한 모금과 함께 생각 하나 삼키기" }

  \],

  "ambient": \["길가의 꽃", "돌담", "바람"\],

  "avoid": \["차량 교행 구간 등 주의 필요 지점"\]

}

- 100썰의 소형 장치들(오늘내일문, 유언비, 등대길, 도로(道路), 황금지 등)이 waypoint 후보.  
- 우선 작성 대상: 관문↔음악정원, 음악정원↔노자예술관, 노자예술관↔와룡, 와룡↔나이야가라, 나이야가라↔도자마을, 각 스팟↔카페알로 귀환로.  
- waypoint가 없는 구간은 ambient(꽃, 냄새, 소리, 발밑)만으로 행위 생성.

### 4.3 나무판 문구 목록 (boards.json) — **수령 대기**

문구 \+ 그 문구가 열어주는 사유의 방향 1\~2줄.

## 5\. AI 설계 핵심

### 5.1 사서 페르소나 — 규율 (상세 설계 별도 문서)

1. 답·해석·조언을 주지 않는다. 질문·행위·갈림길만.  
2. 질문은 한 번에 하나. 꼬리 질문 최대 2회, 강요 없음.  
3. 방문객의 언어를 되받아 쓴다.  
4. 각 스팟 도착 첫 발화는 장소의 목소리(보드 인용 또는 그 문체), 문답·갈림길은 사서의 목소리.  
5. 갈림길·행위의 제시 화법은 페르소나 설계와 함께 확정. *(v0.1의 확정 문구 보류 — 논의 중)*  
6. 짧은 답, 침묵도 존중.  
7. 심리 상담·진단 금지. 위기 신호 감지 시 부드럽게 전문 도움 안내.  
8. 책 편집 시 방문객의 문장을 고쳐 쓰지 않는다.  
9. 카페알로에서는 말수를 줄인다. 나이야가라에서는 가벼워질 수 있다.

### 5.2 여정의 실 (Thread) — 연속성 메커니즘

**"개인의 정보와 고민이 장소의 특성·의미와 연결되어, 도착 과정과 도착 후의 사유가 연속성을 갖는다"** 를 구현하는 장치.

- 스타트 입력 직후 AI가 내부용 한 줄을 생성: *"이 사람은 \_\_\_을 읽고 싶어한다"* 형식. (예: "멈추는 법을 읽고 싶어한다", "아버지와의 침묵을 읽고 싶어한다")  
- 실은 방문객에게 그대로 노출하지 않는다(에필로그의 책 제목·서문에서 변주되어 돌아올 수 있음).  
- 모든 생성 요청에 실이 포함되며, 시스템 프롬프트는 다음을 강제한다:  
  - 이동 중 행위는 실과 무관한 일반 행위가 아니라, 실을 품고 하는 행위여야 한다.  
  - 도착 첫 질문은 이동 중 관찰을 호출한다 ("걸어오며 본 \_\_\_은/는…").  
  - 미션은 장소의 seeds와 실이 교차하는 지점에서 생성한다.  
  - 갈림길의 이유는 실의 다음 챕터가 왜 그 장소에서 쓰일 수 있는지를 말한다.  
- 실은 고정이 아니다: 챕터 2 이후 방문객의 답변이 실과 어긋나면 AI는 실을 조용히 갱신한다 (책의 주제는 쓰면서 발견되는 것).

## 9\. 미결 사항

1. **"이동지점 3개"의 범위** — 카페알로를 포함한 3개인지, 3개 \+ 카페알로 종착인지 확정 필요 (현재 문서는 후자 기준).  
2. **경로 사전(paths.json) 작성** — 신규 필요. 우선 구간 목록은 §4.2. 초안은 코코가 100썰·지도 기반으로 작성 가능하나 현장 검증 필수.  
3. **나무판 문구 전체 목록** — 수령 대기.  
4. **하늘등대 위치 확정** — 지도상 ①/⑨ 양쪽 표기.  
5. **사서 페르소나 상세 설계** — 별도 세션. 갈림길·행위 제시 화법 포함.  
6. **도보·체류 시간 실측** — M2에서.  
7. **여권/비자 동선과 앱 여정의 관계**.  
8. 어머니방의 귀환 경로 삽입 여부(§2 챕터 3 말미) — 기획 판단 필요.
